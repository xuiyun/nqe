# NQE ｜ 原生提问增强

> **先看三行**
> - 它改的不是界面，是 **AI 什么时候停下来问你**。
> - 需要 DSH 带 Web 界面；装完刷新页面就能用，只有改到宿主半边才需要重启。
> - 两个开关都能关，关掉就恢复原样，随时能退。

## 它解决什么

两个具体的毛病，跟界面无关。

**一、它动不动就"任务完成"。**

你让它做一件事，它做到一半觉得差不多了，甩一句"已完成"就收尾 —— 剩下的判断全丢回给你。插件打开后：只要还有下一步需要你回应（选方案、确认效果、提供只有你知道的信息），它必须用提问工具问你，而不是结束本轮。只有任务真的做完、只需要汇报时，才允许直接收尾。

**二、理解错了你也看不出来。**

它听完要求直接埋头做，理解偏了也不说，等你看到成品才发现不对。插件打开后（这一条可以关）：动手前先用自己的话把理解讲一遍，问一句"这么理解对吗" —— 你确认、或者改完，它才开始做。

这两条都是**行为层面**的约束。

## 它怎么做到的

| 层 | 做法 |
|---|---|
| 提示词 | 开关打开时往系统提示里注入一段规则：什么时候必须问、什么时候才允许收尾 |
| 兜底 | 模型这一轮没问就准备收尾 → 往它的收件箱塞一条提醒，让它必须面对"问，还是宣布真的完成"。每轮最多一次，不会死循环 |
| 工具 | 插件自己注册 `ask_user`，不用系统自带的那个 —— 因为自带的答案里装不下图片 |

第三条是它跟原生提问最大的区别：**回答问题的时候可以直接贴图**。截图、报错、界面照片，跟选项和文字一起交给模型，不用先存文件再发一遍。

## 提问面板

界面是次要的，但它确实顺手一些：一屏一题、可翻页、可跳过、可收起；选完右下角那颗键变成提交键。

关掉「提问窗口优化」就退回原生卡片，**上面两条行为规则照旧生效** —— 面板和逻辑是分开的。

## 设置

设置 → 插件 → **NQE｜原生提问增强**。

| 开关 | 作用 |
| --- | --- |
| **提问模式** | 总开关，管着上面两条行为规则 |
| └ 执行操作前向用户确认理解是否正确 | 第二条规则，默认开 |
| **提问窗口优化** | 用不用这套面板；关掉走原生卡 |
| └ 选择答案后自动翻页 | 选完自动下一题；同一页换答案不会跳 |

有额外设置的开关，右边会多一个箭头，点开才看到下面那条。

## 装

```
dsh plugin --profile desktop add github:xuiyun/nqe
```

网页端把 `desktop` 换成 `web`。装完刷新页面；设置页里没出现就重启一次 DSH。

## 常见问题

**它会不会一直问、停不下来？**

不会。兜底每轮最多一次；提示词也写明了"任务真的完成就直接汇报"。

**关掉「提问模式」还剩什么？**

只剩提问面板（如果「提问窗口优化」还开着）。AI 的行为恢复默认。

**贴的图存哪儿？**

本地 `DSH_HOME/attachments`，跟 DSH 自己收的附件放在一起，不上传任何地方。

**答到一半关掉页面会怎样？**

提问会挂十分钟等你；超时之后 AI 当作没答，继续往下走。

**卸载**

```
dsh plugin --profile desktop remove dsh-question-mode
```

## 技术说明

- **工具**：自建 `ask_user`（JSON Schema），走 `/dsh-question-mode/pending` 与 `/answer`；超时 10 分钟
- **提示词段**：`question-mode:policy`，只在开关打开时注入
- **兜底**：监听 `agent/turn-stopping`，每轮最多推一次提醒
- **座位**：`conversation.input.dock`（面板）、`plugins.bundle.config`（设置页）、`conversation.input.attachments`（附件栏）
- **状态文件**：`$DSH_HOME/question-mode.json`（`active` / `optimized` / `confirmFirst`）
- **日志**：`$DSH_HOME/question-mode.log`
- **自测**：`node render-check.mjs`
